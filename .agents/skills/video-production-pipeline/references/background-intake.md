# 项目背景采集流程

在任何涉及具体产品、品牌、服务或组织的创作前执行。此流程可按风险和任务范围简化，但事实核验不能省略。

1. **确定项目边界**：确认当前项目名称、业务主体、产品/服务范围、内容渠道和本次需要的交付类型。不要沿用其他项目档案。
2. **采集核心信息**：使用 `project-background-template.md`，向资料持有人收集产品/服务、实际用途、用户/购买者/决策者、适用条件、限制、可验证差异点和期望的下一步。
3. **登记依据**：每项可验证的对外主张注明原始资料、链接或负责确认的人、有效日期/范围和是否可公开。营销描述不能替代证据。
4. **显式处理缺口**：把缺少来源、冲突、过期或权限未知的字段列入待确认表；在得到确认前，不将其包装成肯定陈述，也不基于其设计承诺。
5. **确认表达与素材权限**：核实合同/收益/性能等高风险陈述的批准方式；确认 Logo、图像、人物、客户案例、音乐、字体和生成工具使用范围。
6. **建立项目档案**：按当前项目单独保存档案，记录版本、确认人和更新日期。每条任务只引用该档案中适用于该渠道/日期的信息。
7. **变更时更新**：新增事实由项目负责人确认后更新档案；保留变更记录，不把单条假设或创意升格为长期事实。

如用户已经提供足够且已确认的信息，可直接整理成档案并标清哪些内容仍待确认；不要重复追问已知事实。
