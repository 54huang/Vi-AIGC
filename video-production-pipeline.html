视频生产流水线
一套核心，适配不同项目

这不是某个品牌或某种画风的专用方案，而是一台可配置的内容生产机器：先采集并确认项目/产品背景，再将每条视频的 Brief 转换成可执行的声音、画面与制作任务，通过资产连续性、预演和 QA 降低漂移与返工。

恒定：生产方法与质量门禁配置：项目背景与品牌事实单条：主题、音乐、规格与素材工具无关：实拍 / 动画 / AI / 混合
框架分层产品背景流程生产流水线交付合同连续性质量门禁单条任务卡复用与维护
01

框架分层：不要把项目配置误当成生产核心

新品牌、新产品、新风格进入时，替换配置，不重写流水线；没有确认的配置不自动补全。

A · 通用生产核心

所有视频任务重复使用

  • 背景核验、事实分级、授权纪律。
  • 从创意到交付的制作顺序。
  • 声音、分镜、资产台账的输出规范。
  • 质量门禁、返修和复盘方式。
B · 项目配置

每个项目独立维护

  • 项目/品牌、产品/服务和主体关系。
  • 受众、场景、证据、禁区与可公开主张。
  • 平台、风格、语气、素材与长期设定。
  • 确认人、版本、日期和授权范围。
C · 单条 Brief

每条任务分别填写

  • 本期目标、观众问题和核心结论。
  • 指定音乐、时间长度、格式和资源上限。
  • 本期引用的资产与特殊限制。
  • 需要的交付阶段与唯一行动请求（如需要）。
防串项目：项目设定必须有项目范围标记；本条临时风格不写回长期档案；没有给定平台、时长、画风或 CTA 时，先询问或提出可选建议，不冒充既定默认。
02

产品背景流程：保留“先了解，再创作”

背景档案是输入采集和事实管理流程，不是让模型自由发挥的产品说明。

1 · 界定项目主体、产品范围、渠道与交付
→
2 · 采集背景用户、购买者、场景、流程、限制
→
3 · 登记证据来源、日期、范围、确认人、可公开性
→
4 · 标记缺口冲突、过期、未知与待确认
→
5 · 确认表达禁区、承诺、素材及授权边界
→
6 · 建立档案项目独立保存，版本化维护

每个项目档案建议包含

  • 项目身份、产品/服务类别和实际提供范围。
  • 解决的问题、目标用户、购买者/决策者和使用场景。
  • 已确认差异点及证据；不包含的内容、适用限制和例外。
  • 事实/观点/假设分类，出处、适用范围、有效期、公开权限及审批人。
  • 品牌声音、视觉/渠道设置（均可配置），禁用表达与合规审核人。
  • 素材、人物、Logo、音乐、字体、客户案例等权限范围和期限。

档案缺失或冲突时怎么办

  • 可以先做不依赖未确认主张的通用构思。
  • 产品功能、效果、客户、资质、价格、收益等不确定信息标记待确认，不能补造。
  • 资料冲突时列出来源与差异，交由项目负责人裁决。
  • 素材授权不明时不当作可用素材；需发布前再核对时效事实和平台规则。
  • 新确认信息写入项目档案，记录版本、日期与确认人；单次创意不写成长期事实。
03

生产流水线：每一步有交付物，也有停点

先明确内容目标与证据，再选择工具；流程不绑定任何生成器、剪辑器或供应商。

0 · 加载背景使用项目档案，标缺口
→
1 · Brief目标、观众、问题、资源
→
2 · 创意定题一个结论、一条故事线
→
3 · 声音/脚本分析音乐或给待选方向
→
4 · 视觉/分镜资产、时间码、三轨脚本
→
5 · 预演静帧 / storyboard / animatic
→
6 · 制作 QA代表镜头后扩展、逐镜检查
→
7 · 复盘投入、返修、复用、数据

核心创作次序

  1. 锁定受众问题、核心信息和叙事因果。
  2. 有实际音频时先分析可听特征；无音频时提供待选音乐方向，不伪称听过。
  3. 按音乐段落安排旁白断句、停顿、镜头节奏、动作、转场和音效/留白。
  4. 选择与项目设定匹配的视觉路线；需要连续性时先建立参考资产。
  5. 用低成本预演验证逻辑和时长，再扩大制作。

收束内容，避免一条过载

建议每条锁定：一个主要目标、一个观众问题、一个核心结论、一个记忆锚点和一个 CTA（若本条需要）。开场的悬念或承诺必须在正文兑现。节奏由理解难度和音乐结构决定，不机械规定每几秒切一次镜头。

目标时长由项目/任务配置。根据实际口播试读核算，不用硬凑字数；平台规格在导出前核验。

04

标准交付合同：按时间段写清楚视听关系

完整方案的每个时间段都能被制作人员直接执行；简短任务只交用户需要的部分。

交付部分必需内容目的
本期创意卡目标、观众、问题、结论、记忆点、证据、风险、故事梗概控制单条主题边界
音乐方案实际音频的听感与段落分析，或标为待选的情绪/速度感/音色/结构及搜索线索避免音画后期硬拼
完整旁白可录制口语稿，标出停顿、重点、语气及预计口播时长可直接试读、录音
逐段分镜时间码、景别/构图/动作、字幕、声音、音乐段落、同步音效/留白、资产引用将抽象创意转成生产指令
故事描述从开场到结尾连贯讲述观众看到的变化、因果和情绪推进让团队脑中形成一致画面
制作与 QA素材清单、生成/拍摄提示、事实/授权检查、返修点、导出核验降低遗漏和整批返工
三轨原则：画面轨说明“观众看到什么”；文字轨保证静音时抓住主信息；声音轨说明口播、音乐与音效。字幕不是整段口播的文字墙，动作音效要有明确同步点或明确留白。
05

资产连续性：固定身份，只改变本镜动作

参考图、版本台账、预演和人工复核降低漂移概率；不能保证生成模型绝对一致。

视觉设定表（仅在需要时启用）

  • 人物/产品/道具/场景/UI 的固定身份特征。
  • 色彩、材质、比例、视角、文字/Logo位置和不能变化的细节。
  • 允许改变的姿态、表情、机位、状态和背景元素。
  • 参考素材路径、资产 ID、版本、审批及使用权限。
  • 项目风格和品牌识别元素；没有项目资料不自设风格锁定。

逐镜连续性台账

镜号资产/版本状态/位置场景/光色本镜变化下镜交接检查
01项目资产 ID当前状态与画面位置当前设置只写需要的动作变化下一镜承接状态待检/通过
02同一版本或明确新版本接续上一镜确认变化或保持限制漂移范围为后续镜头留状态待检/通过

模型不支持稳定引用参考图时，可使用同素材局部编辑、后期合成、剪辑遮罩或人工筛选；在产出要求中提前说明剩余风险。

06

G0—G4 质量门禁：问题在高成本制作前暴露

任何关键项未通过都要记录返修范围；导出完成不等于内容验收通过。

G0 · 背景与选题

事实和方向成立

项目档案版本有效；目标、受众、问题、核心结论、证据和资源边界明确。

阻断：关键产品事实无来源或选题过宽。

G1 · 脚本与声音

方案能录、能做、能听清

旁白试读可达时长；音乐分析可信；动作、音效、字幕和故事因果明确。

阻断：虚构听感/授权、叙事不通或人声不可辨。

G2 · 低成本预演

批量制作前看一遍

用静帧/粗动画/占位镜头检查顺序、时长、视听节奏和连续性。

阻断：预演未批准，不投入整批高成本生成。

G3 · 成片与授权

逐镜验收

核对事实、字幕、手机端可读性、授权、声画、连续性、封面与规格。

阻断：事实/权限未知或关键视听问题未修复。

G4 · 复盘

记录实测，不套爆款结论

记投入工时、修改轮数、资产复用、表现数据来源与统计时间窗。

输出：下一轮只设一个可验证改进点。

稳定性边界

可标准化任务卡、脚本结构、资产命名、审批状态、字幕规范与 QA。模型画面细节、文字、物理运动、音乐授权和平台分发不能由提示词完全控制。

07

通用单条任务卡

每次调用只填这条视频的差异项；缺字段标“未知/待确认”，不要让模型默认某品牌设定。

【项目/背景档案】项目名、档案路径、版本；未建立则标记 【本条主要目标】 【目标观众】 【观众问题/需求】 【核心结论】看完后只需要记住： 【记忆锚点】一句话/一个画面/一个动作/一个声音（可选） 【平台与规格】明确填写；未定则说明 【目标时长】明确填写；未定则说明 【本条题材与故事情境】 【音乐/声音输入】指定曲目/音频/链接，或请求待选方向 【本期可用事实与来源】 【引用视觉/声音资产】ID、版本、路径、授权状态；无则标待建立/不适用 【制作路线与资源限制】实拍/动画/AI/混合；工具、预算、工时 【本条 CTA / 下一步】仅在任务需要时填写 【本轮交付】选题 / 旁白 / 完整分镜 / 生成提示词 / QA / 其他 【单条覆盖】需区别于项目档案的临时设定；未写则不覆盖
局部修改时的固定指令

请仅按明确反馈修改当前版本。保持未被点名的项目事实、受众、结论、视觉/声音设置、时长和已批准资产不变。先简述修改范围，再交付完整修订版和改动列表。若改动影响事实、授权、口播时长、音乐、镜头动作、连续性或导出设置，同步检查受影响内容并标出仍待确认事项。

08

如何真正复用：项目内规则如何落地

固定核心写在 Skill 与工作流；项目事实写在独立档案；单条变量放进任务卡。

常驻核心资源

  • .agents/skills/video-production-pipeline/SKILL.md：任务路由与核心约束。
  • references/production-workflow.md：固定生产顺序、交付结构、连续性、质量关卡和返修规则。
  • references/project-background-template.md：新项目背景档案模板。
  • references/background-intake.md 与 project-profile-governance.md：资料采集及档案维护流程。
  • references/upstream-principles.md：外部工作方法筛选和授权纪律。
  • openspec/specs/video-production-pipeline/spec.md：行为契约，定义流水线必须满足什么。

更新纪律

  • 稳定的方法改在工作流；新需求先更新 OpenSpec。
  • 产品事实只写入对应项目档案，注明来源和确认状态。
  • 单条创意只留在单条产物，不升级为项目默认值。
  • 修订应同时核对 Skill、参考文件、任务卡和本页避免彼此冲突。
  • 结构化记录可选试点包含 ProjectProfile、VideoBrief、Claim、Asset、Shot、Review、Release、GateChecklist、GateRun 与 GenerationManifest；使用稳定 ID 和精确版本串联门禁证据、输入权利、模型/工作流、输出哈希及最终剪辑引用。
  • G0–G4 记录 pass / fail / blocked / not-applicable、证据、责任人和规则/工具/配置版本。缺前提为 blocked；PASS 只证明确定性规则通过，不替代事实、授权充分性、品牌适配、可读性、审美与合规的人审。
  • 代码、模型权重、输入素材和输出使用条件分开记录，开源或 Model Card 不推导商用权限；对象或关键配置变更须重跑受影响检查。
  • 外部工具或平台规范随时间变化，使用前单独核验；不写死模型能力与价格。
结构化记录（可选）：需要跨阶段追踪时，可使用 production-data/ 的 YAML/JSON Schema 和本地验证器，将档案、Brief、主张、素材、镜头、审查与发布记录用稳定 ID 和版本连接。验证器负责确定性完整性与关联检查；内容真假、恰当性、授权充分性、审美及合规必须由责任人审核，不能由 PASS 替代。
归纳：核心管怎么做；项目背景管“这是谁的产品、能说什么”；单条 Brief 管这次讲什么。三者分开，才能让同一条流水线稳定服务不同项目。
