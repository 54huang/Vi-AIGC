# Design

## Context

现有 G0–G4 已定义阶段目标，结构化生产数据已能表达 ProjectProfile、Brief、Claim、Asset、Shot、Review 和 Release，并校验基本字段、关联、版本、有效期及审查要求。但门禁结果仍主要以叙述形式记录，缺少逐项结果/证据契约；Asset 也不足以表示一次模型生成或加工执行的完整输入、权利、环境、输出与下游引用链。设计沿用仓库已有的离线优先、JSON Schema + YAML/JSON + Python 验证方式，不引入服务端平台。

## Goals / Non-Goals

**Goals:**
- 让每个 G0–G4 检查项能被机器定位、责任人复核并绑定精确版本。
- 用可复现工具先覆盖确定性媒体条件；遇到未知前提时显式 `blocked`。
- 将资产来源、权利维度、生成执行、输出哈希、审查与 Release 串成轻量可追溯链。
- 保留 Markdown 工作流并支持渐进采用；机器结果不得替代专业判断。

**Non-Goals:**
- 不做媒体内容语义判定，不自动证明事实、授权充分、品牌合适、易读、美观或法律合规。
- 不引入数据库、云端登记服务、特定模型供应商或自动法律意见。
- 不强制保存可能含隐私/机密的明文提示词、密钥或原始媒体副本。
- 不将“开源”或模型卡标签当作商业权利结论。

## Decisions

### 1. 门禁采用独立、版本化的 Check 与 Run 记录

清单定义阶段、稳定 `check_id`、规则版本、检查说明、责任类型（自动/人工）、阻断级别、所需输入及显式配置项。单次执行另存结果记录：运行 ID、清单版本、check ID/规则版本、目标对象及版本、状态、证据引用/摘要、执行人或责任人、时间、工具/配置版本、诊断和替代/重跑关系。清单定义不等于执行结果；结果历史追加保存，不覆盖。聚合判定按清单阻断级别计算；`not-applicable` 需理由、责任人，且仅可在规则允许时豁免。

自动与人工检查共享结果外壳，但 `checker_type`、执行者、证据类型需明确区分。自动 PASS 只表示该项确定性断言通过。针对对象/依赖/规则或关键参数的变更，通过精确版本比较使旧结果失效，而不是删除旧证据。

### 2. 先做确定性且可测的本地媒体检查

首批检查范围：存在性与引用完整性、容器/编码/分辨率/帧率/声道等配置化规格、时长、字幕轨道时间码边界/覆盖率、配置化音频峰值和授权记录的必填/到期字段。阈值归 ProjectProfile 或独立配置版本所有，不在框架中擅设统一业务阈值。媒体探测工具适配器须报告工具/版本、输入哈希与测量结果；缺工具、损坏媒体或必要阈值缺失返回 `blocked`。音频峰值的测量口径（如 sample/true peak）需在规则中显式指定，避免工具间口径不一致。

这类检查仅对机器可观察的条件负责。授权条款含义、用途是否落在许可范围，以及事实、品牌、字幕可读性和成片质量等由 Review 责任人作出结论。

### 3. Asset Registry 复用现有 Asset 并补充 Manifest

Registry 不新造平行的资产主键体系：Asset 继续作为可复用内容实体，增加来源/权利元数据及其版本；Manifest 表示一次生成/加工事件和执行环境，具有自己的稳定 ID/version，并引用输入 Asset 精确版本及输出 Asset 精确版本。输出仍登记为 Asset，文件由 URI/相对路径引用并用算法+摘要校验完整性。Review 继续引用被审对象精确版本，新增关联到 Manifest 或其输出 Asset。Shot 与 Release 引用实际使用的 Asset 版本；Release 仍校验素材引用闭包。

权利数据按代码、模型权重、输入素材、输出使用条件分离，包含权利来源/记录、权利人或提供方、范围（用途/渠道/地域/期限等）、状态、到期日及人工核验 Review。字段完整/期限未到期是机器可查事实；许可解释和可商用结论是人工判断。Model Card 可作模型信息来源/证据，但不替代素材逐项权利核验。

工作流与提示词尽量以 ID/version/hash 引用，参数按结构化字段记录；若含敏感内容，可使用权限受控的位置引用或哈希，并记录访问方式/保管责任，避免凭据入库。

### 4. 兼容迁移

保留目前 Markdown + 结构化记录并行的兼容方式。已有普通素材 Asset 不要求伪造生成参数；manifest 对来源于生成/加工流程的新资产以及主动迁移的资产为必需。旧数据包可使用旧 schema 版本继续校验，声明使用新增能力时才要求新 schema/manifest/门禁结果；升级工具须报告迁移缺项，不将缺项静默填成 PASS 或许可结论。

### 5. 验收以契约和 fixture 为准

为清单、运行记录、权利字段、manifest、变更关系编写 Schema 与正/反样例。测试分别覆盖结构校验、门禁聚合/失效、资产图连通性、哈希匹配、权利维度隔离，以及媒体探测器的成功/失败/blocked。媒体测试使用小型、许可清晰的合成 fixture 或 mock adapter，不依赖外网模型服务。更新 Skill、生产数据说明、迁移指南、README 与 HTML 概览，使其描述一致。

## Risks / Trade-offs

- 检查项过多会增加制作负担：首版保持最小清单，允许按项目配置，但不得任意删除强制项。
- 媒体探测结果受工具实现影响：记录版本、算法口径和输入哈希，并以固定 fixture 回归。
- 权利元数据无法自动解决法律解释：清楚标示“记录完整”与“人工授权通过”不同，发布仍受人工 Review 控制。
- 本地文件可能移动：引用优先使用项目相对路径/可控 URI，并用哈希验证内容身份；路径变化需有迁移记录。
- 历史工作流缺少追溯字段：保持旧版本可读，以明确迁移任务逐步补全，不伪造历史来源。
