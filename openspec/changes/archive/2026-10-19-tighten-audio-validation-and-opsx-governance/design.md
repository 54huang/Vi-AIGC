# Design

## Context

见 proposal.md。现有流程是 G0–G4；`GateChecklist`/`GateRun` 可记录人工与自动项，`check_media.py` 只测规格、时长、字幕时间边界/覆盖率与 sample peak。既有 Markdown 工作流与结构化记录并存，不能因新增声音规则而要求所有项目立即迁移。报告中的测试素材仅在本机，不能纳入仓库或发布。

## Goals / Non-Goals

**Goals:**
- 尽量复用 G1/G2 清单和 GateRun，不新建普遍必经的 G1.5 阶段。
- 对有旁白项目在昂贵整轨制作前留下人工声音选择证据；对无旁白任务保持明确 N/A。
- 为 G2 的可选量化指标建立不混淆单位/输入/时窗的证据路径；旧版配置继续可用。
- 明确低成本验证范围与升级条件，并将全仓库 OPSX 约束写成 Agent/贡献者可执行指令。

**Non-Goals:**
- 不设全平台统一的 6–8 dB、-1 dBTP、-14 LUFS 或字幕 ±100 ms 通过线。
- 不用机器判断音色审美、事实、权利或平台适配；不把验证样片当正式成片。
- 不要求所有既有 Markdown 项目一次性补齐结构化生产数据，不提交内部测试品牌或音视频文件。

## Decisions

1. **G1 声音确认使用既有清单模型。** 为有旁白且进入整轨制作的项目，在 G1 清单中加入可审计人工项；样片可为选定候选而不强制恰好 2–3 个/15 秒。证据绑定旁白脚本与声音方案的版本、参数/适用性、选择人及时间；改版本重审。若无旁白，项目清单允许 N/A 且必须有理由和授权人。相比新增 G1.5 阶段，这避免破坏 G0–G4 枚举及历史数据。
2. **G2 分层验收。** 保留现有媒体规格/sample peak 检查；按项目配置启用整体响度/真峰值及可分轨的 VO 与音乐床指标，输出工具版本、来源哈希、时窗/去静音方法、阈值、实测值和单位。未提供分轨时不得从混音的不同时段估计人声与音乐的同步差；若该项必需则 `blocked`。有听感或音画协调的人工检查项仍由人审。优先复用 ffmpeg/ffprobe，不新增常驻平台或数据库；已有 1.0.0 媒体配置维持原语义，扩展字段的 schema 版本和向后兼容在实施中明确测试。自动化只覆盖可复现指标，不承诺自动测量人声/字幕语义同步。
3. **验证档是任务契约，不是硬编码交付上限。** 在 Brief/工作流记录验证目标、必要最少产物、停止/升级条件及未覆盖门禁；预演/成片范围仍由需求确定。结构化采用项目可选字段或关联证据，不破坏已有必填字段。方案中给出可选示例，不能因少做素材而自动批准发布。
4. **仓库治理与生产规则分层。** 新 capability 管仓库贡献行为；AGENTS.md 用祈使形式要求所有拟保留变更先 OPSX、propose 与 apply 分开、实施后测试、同步适用规格再归档。README 的“建议”改为“必须”；仅临时构建缓存/只读调查不属于拟保留修改。无需为小改动造规格变化：可使用无 delta 的合法文档维护变更。HTML 按现有 Agent 规则核对，只有内容落后时同步并验证锚点/响应式布局。

## Risks / Trade-offs

- [试听确认拖慢轻量任务] → 仅对有旁白且计划整轨的任务启用，候选数量和样片时长按项目裁剪。
- [测量工具可用性或口径不一致] → 指标逐项启用，记录依赖与版本；必需项缺前提时 `blocked`，不能冒充通过。
- [配置扩展破坏旧项目] → 测试旧版配置原行为和新增配置；文档说明升级/回退路径。
- [流程强制化增加小修改成本] → 允许精简方案和任务，但不允许无 OPSX；纯文档无行为变化不制造 delta spec。
- [内部样本权利和隐私风险] → 本地只读回归，自动测试使用生成/合成临时素材；不提交昼白文件或对外发布。

## Migration Plan

1. 先加 G1/G2 参考清单、验证档说明及 Agent/README 规则；保留现有 G0–G4 状态与既有配置。
2. 增加可选测量配置/结果与回归测试；旧配置及 Markdown 产物可原样运行，项目启用新指标前明确输入和阈值。
3. 使用本地内部样本检验人工与媒体路径，同时以无旁白/缺分轨/缺工具的合成测试检查 N/A、blocked；只提交代码、样例与不含测试素材的结果摘要。
4. 实施通过后核对 HTML，执行完整验证；按 OPSX 同步两个主规格并归档。若新测量不稳定，可停用可选指标并保留现有 sample peak 检查，不放宽发布门禁。
