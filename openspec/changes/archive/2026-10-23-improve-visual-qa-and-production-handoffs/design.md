# Design

## Context

见 proposal.md 与 delta spec。仓库当前以 `video-production-pipeline` 文档和可选 `production-data/` YAML/Schema/本地检查器实现 G0–G4；媒体检查以规格、字幕、音频为主。好礼乐 v0.2 报告使用 96×170 灰度加模糊运动量，组合版 v0.3/v0.4 使用 270×480 解码；报告中的外部 G 阶段名与仓库正式阶段并不一致。三个报告分别为本地来源，SHA-256：v0.2 `FCE85F2A04EAFF747B988964F8171BDA31100845778EA031C029E1A176F8654A`、v0.3 `6E62CAC4DEB98BD561DCF46CA7249C2628DD87537BE001CA2ED7C3CBF7502216`、v0.4 `6ED75E3591A9CDE062C41359B0A7D2D6A7675EC2D085EF2FB1EAFD761F7940C1`。这些是报告哈希，不是成片媒体哈希；未经原视频复测的指标只能引用为报告观测。

## Goals / Non-Goals

**Goals:**
- 保留带方法与版本的视觉证据，辅助审片定位和相同口径下的回归，而非自动替代创意审查。
- 让复用动效、资产交接和多工具制作能够落在原有 Shot/Asset/GateRun/Release 关系上。
- 三份报告可作为公开安全的案例索引，并能追溯到具体优化/测试，不混同外部 Skill 的门禁标签。

**Non-Goals:**
- 不把 v0.2 的 MAD 81.5% 与 v0.3/v0.4 的约 56–57% 直接解释为创意改善幅度；分辨率、滤波、场景与帧率不同。
- 不在本仓库复制、实现或分发 `video-shotcraft`、`remocn` 或其组件/素材；不把报告中品牌 Logo 视为已授权。
- 不设统一静帧比率、MAD、品牌色面积、SFX 对齐时差或视频码率硬阈值；不自动判断“好看”“推开而非消失”或文字可读。
- 不另建通用视频编辑平台、数据库或重新定义 G0–G4。

## Decisions

1. **视觉诊断独立于媒体规格通过判定。** 新增轻量、可选的 `check_visual.py` 及版本化配置/schema，输出 JSON，保留视频 SHA-256、分析方法/工具版本、scale/灰度公式/滤波/采样、每帧差分及聚合口径、场景边界、重叠处理、抽帧索引和有限统计。默认产出 `informational` 诊断；项目启用且提供阈值的客观规则才产生 `pass/fail/blocked` 检查，映射至现有 GateChecklist/GateRun，人工逐场 Review 独立。相比直接向 `check_media.py` 加固定“审美 PASS”，这隔离了非同质指标，并保留旧配置行为。实现优先使用现有 ffmpeg/ffprobe 与 Python 库，新增依赖应由实施前明确记录、测试其缺失时 `blocked`。
2. **场景与帧统计口径。** 输入可为明确时间轴/shot frame ranges 的小型 sidecar（绑定 Shot ID/version，可无结构化项目时用明确标签），先检查视频 fps/帧数，再标明区间 `[start,end)`，重叠转场可通过“独立片段统计、全片仅计一次”规则消除双计，结果同时记录来源重叠。不使用同一帧在两个场景中的计数去伪造全片高能事件；0.2 的预处理与 0.3/0.4 必须独立标识 `analysis_profile`，不相同则不出跨版自动结论。视效预算为制作计划的人工提示，非全项目事件数强制上限。
3. **动效与跨工具交接保持工具无关。** 在 references/模板中定义 MotionRecipe（示例可选配方，包括转场、入场、推出）和 handoff 表；对外部工具原始阶段名、工具版本、导出路径/哈希、资产/镜头版本、帧率/原始总帧/过渡重叠/净帧、音频尾部和人工审查引用做映射。必要的结构字段可用轻量 JSON/YAML Schema/验证器增量加入 `production-data/`；不强制普通 Markdown 项目迁移，也不声明第三方实际使用许可。复用的是方法和参数记录，不是外部二进制或项目品牌资产。
4. **版本差异评审与可比性。** v0.4 的 Logo/定位语/配色替换以“影响矩阵”定位到 Claim/Asset/Shot/Review/Release；旧视频和新视频分别保留精确哈希与审核状态。已有记录/门禁失效机制优先复用，补变更例子和验证测试，不仅因为旧版本视频音频参数合格就写新版本发布 PASS。对比报告记录视频帧数÷fps 和容器 PTS 时长（v0.4 900/30=30.00s，容器 30.06s），不把二者混用。
5. **三份报告的知识封装。** 仓库仅收敛公开安全的报告摘要、原文件名/报告哈希、测量条件、关键差异、发现—优化—回归条件和未验证结论；音视频、Logo 与完整业务资料不入库。此前昼白变更单独保留；后续若要合并/废止它，需另一轮显式更新或归档决策。

## Risks / Trade-offs

- [MAD 对低对比平移/滤波敏感，会误判运动] → 输出采样条件和视觉抽帧，提示人审；不使用统一硬阈值代替质量判断。
- [全帧解码成本高] → 提供可配置缩放/时窗、资源上限与失败诊断；测试短合成片，长片逐步处理，不把性能优化凌驾于可复现性。
- [可选配置打断旧项目] → 新 schema 版本或独立配置，旧 `check_media` 配置/示例保持兼容；缺少工具或规则前提明确 `blocked`。
- [外部 Skill 的 G2/G3/G4 标签撞名] → 记录原标签、来源及映射，不自动转为仓库门禁。
- [品牌资产/报告隐私与许可] → 只录技术摘要和报告哈希，权利待人审；无仓库外不可访问的下载链接。

## Migration Plan

1. 先补工作流、配方/交接模板与项目级视觉配置示例，不改变旧项目要求；以合成素材开发独立诊断和负例测试。
2. 本地只读抽查三份报告与可用媒体，形成经口径注释的案例文档；不可复测的数据标为“报告数据”。README 添加入口、HTML 按 AGENTS.md 同步实质差异并校验。
3. 完成旧/新配置、重叠帧、缺工具/阈值、改版失效和人工未签认的回归，严格 OpenSpec 校验后另行 sync/archive。回退时停用可选视觉配置，旧媒体检查及主记录继续可用。
