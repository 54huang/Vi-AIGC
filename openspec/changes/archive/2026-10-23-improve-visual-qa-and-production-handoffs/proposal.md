# Proposal

## Why

好礼乐 v0.2 隔离测试显示音频/容器检查可通过，但场景内部动作、内容密度与可见性仍可明显不足；v0.3/v0.4 多 Skill 组合测试又暴露了帧预算、跨工具门禁名称、声画事件、品牌资产改版与复核证据需要统一交接的问题。单靠现有媒体规格校验或未经归一化的 MAD 数值，既不能定位这些返工点，也不能证明画面好看、品牌合适或已获发布许可。

## What Changes

- 为预演/成片增加**可选、项目配置的视觉诊断与人工逐场审看**：从解码视频导出逐场/逐秒运动与静止区间、场内/切点事件、取样帧、亮度/对比和可选项目色统计；记录方法、尺度、阈值、输入哈希和工具版本，结果定位问题而不自动判审美。只有项目明确配置的客观界限才能形成门禁检查，缺前提为 `blocked`。
- 增加可复用的**镜头/动效配方与资产交接模板**，明确用途、可调参数、起止帧、可见性风险、素材 ID/版本/权利、低成本代表镜头及失败回退；不把特定第三方库或好礼乐视觉风格纳入核心默认值。
- 增加**跨工具制作交接与版本差异复核**：把外部 Skill/渲染器的阶段映射至本仓库既有 G0–G4，核对重叠转场的净帧预算、视频帧时长与容器时长的区别，并在旁白、Logo、文案、调色等改版时重审受影响镜头、声音、品牌/权利与 Release 引用；第三方工具的局部“通过”不能冒充本仓库正式门禁。
- 在仓库封装三份好礼乐报告的可公开测试摘要、口径差异、发现—优化—回归矩阵和 README 入口；此前昼白复盘提案保持独立、暂停实施，不将缺失的昼白媒体与本轮证据混用。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `video-production-pipeline`：扩展低成本预演的视觉证据与人工审阅、工具无关的动效/资产交接，以及多工具和改版场景下的帧/门禁/审查追溯要求；沿用既有 G0–G4、结构化记录与人机审核边界。

## Impact

预计影响主规格的 delta、生产 Skill 与 references/模板、`production-data` 的可选视觉诊断配置/工具/测试和集成示例、测试复盘文档、README 与 HTML 概览。以现有媒体/门禁模型渐进扩展，不强制既有项目迁移，不新增数据库或第三方运行时依赖；仅处理三个报告中可公开的摘要和源文件哈希，不提交 `D:\video test` 的媒体、Logo 或未核验授权材料。当前 `capture-pipeline-test-retrospective` 保持原状，本变更不自动合并、归档或删除它。
